# Парный замер oxide_parse v8.3 и v8.4.1

v8.3 взята из коммита `5074b69`. v8.4.1 взята из рабочей копии с исправлениями.
Обе сборки release/full, Windows x64, Rust 1.99.1 и один CPython 3.13.7.

Для каждого сценария выполнены 16 раундов. В половине раундов порядок был ABBA, в половине BAAB, где A — v8.3, B — v8.4.1. Порядок сценариев перемешивался. Два наблюдения каждой версии усреднялись внутри раунда. Время включает извлечение и создание Python-результата. Старт процессов, компиляция плана, генерация HTML, сборка мусора и проверка результатов вне таймера.

Входные байты и результаты попарно сверены по SHA-256. Бинарные расширения имеют разные хэши. Конфигурация не фиксировала частоты CPU или фоновую нагрузку.

## Пакетный ремонт восьми полей в одном контейнере

| API | Вызовы callback | Суммарный размер JSON | Медиана локального времени |
|---|---:|---:|---:|
| `repair` | 8 | 16 442 байта | 1.538 мс |

32 чередующихся раунда на v8.4.1. В обоих режимах извлечены одинаковые восемь значений.
Время включает разбор, ремонт и сериализацию аргументов callback. Callback возвращал
заранее заданные селекторы. Время сети, генерация ответа моделью и число токенов не измерялись.

## Проверки сборки

- Rust full — 106 тестов прошли.
- Rust scraper-only и lite-only — оба `cargo check` прошли.
- Windows release/full wheel — 1200 Python-тестов прошли, 196 пропущено, 13 ожидаемых падений.
- Conformance — 0 FAIL и 0 ERROR. Pre-commit и mypy прошли.
- Дополнительно проверены 64 и 65 последовательных `follow`, JSON глубиной 80 уровней
  и асинхронный пакет, где один селектор принят сразу, а второй сохраняет ID и получает
  сообщение CSS-парсера перед повторной попыткой.
