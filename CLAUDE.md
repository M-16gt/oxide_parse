# CLAUDE.md — Repository Contract for `oxide_parse`

## Layer Architecture

```text
Python DSL (T)  ──to_ir──►  IR (JSON/YAML)  ──Plan::compile──►  Eval<Dom> / StreamPlan
python/oxide_parse/         crates/core/src/ir.rs                crates/core/src/
```

- `crates/core/src/`: pure Rust core with zero IO and zero Python dependencies.
  - `ir.rs` — `Expr` and `Op` AST definitions (serde).
  - `plan.rs` — compilation, selector deduplication, peephole rewrites (`select | text -> select_first | text`, `parse_json | key -> json_path`), `explain()`.
  - `exec.rs` — generic executor over `trait Dom`, `Session` state machine (`follow` / `paginate` fetches + `adaptive` repairs), `json_cache` and `js_json` cache.
  - `markup/` — shared zero-copy tokenizer, HTML tree-builder rules (`events`), CSS parser, and arena DOM (`lite` and `stream`).
  - `xpath/` — shared XPath 1.0 evaluator over `Dom`.
  - `adaptive.rs` — element fingerprints, similarity relocation, `MemoryStore` and `FileStore`.
  - `engines/` — cargo-feature-gated engines (`scraper`, `lite`, `stream`, `json`), registry in `engine.rs`.
- `crates/py/src/lib.rs`: PyO3 bindings (`Plan`, `Session`, `engines()`, `distill()`, Rayon `extract_batch` / `extract_many` with the GIL released).
- `python/oxide_parse/`: `expr.py` (DSL), `plan.py` (sync/async drivers, persistence), `decompile.py` (IR to Python), `ir_spec.py` + `ir.schema.json` (validator and JSON Schema), `migrate.py` (deterministic converters), `prompts.py` (prompt texts), `__main__.py` (CLI).

## Non-Negotiable Invariants

1. **Zero IO in the core:** neither the Rust crate nor `oxide_parse` in Python ever performs network requests or calls LLMs on its own. `follow`, `paginate`, and `repair` emit requests through `Session` or user callbacks.
2. **Null propagation:** missing elements or `None` inputs evaluate to `None` without raising. Only `.required()` and `.default(...)` decide on missing values. Extraction errors always carry a path (`$.items[3].price`).
3. **Engine parity:** for any streamable schema, `stream`, `lite`, and `scraper` must return identical results (verified in `crates/core/tests/`).
4. **Single IR table:** whenever you add or modify an `Op` in `crates/core/src/ir.rs`, synchronize `python/oxide_parse/ir_spec.py`, `decompile.py`, `expr.py`, and regenerate `ir.schema.json` (`python scripts/gen_ir_schema.py`).
5. **Version & stub alignment:** versions must match across `pyproject.toml`, `crates/core/Cargo.toml`, `crates/py/Cargo.toml`, `Cargo.lock`, `python/oxide_parse/__init__.py`, and `docs/architecture/publishing.md`. Every `#[pyfunction]` and PyO3 method must appear in `python/oxide_parse/_core.pyi`.
6. **Tested documentation:** keep `README.md` at `<= 280` lines; Python code examples in `README.md` and `docs/guide/*.md` are executed by `tests/test_docs_examples.py`, module doctests and English-only checks run there too, and `llms.txt` / `llms-full.txt` are generated by `scripts/build_llms_txt.py`.

## Verification Commands

```bash
# Rust tests and feature-isolated builds
cargo test -p oxide_parse-core --locked --features full
cargo check -p oxide_parse-core --locked --no-default-features --features engine-scraper
cargo check -p oxide_parse-core --locked --no-default-features --features engine-lite
cargo check -p oxide_parse-core --locked --no-default-features --features fast

# Build Python extension and run all checks
uv run maturin develop --release --features full
uv run pytest -q
uv run mypy
python scripts/gen_ir_schema.py --check
python scripts/build_llms_txt.py --check
```
